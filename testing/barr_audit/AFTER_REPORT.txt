BARR-C changes and verification - 2026-11-26

Status: common application layout rules fixed; full BARR-C compliance is
NOT established. The original REPORT.txt and *_checker.txt files are the
before-change audit. after_style.txt records the passing selected checks.

Changes
- Applied an explicit common clang-format 21 profile across all 148
  application C/header files and the existing B1/B4 host checker scopes.
- Added braces to standalone control bodies, Allman layout, 80-column
  wrapping, spaces in place of tabs, LF endings and final EOF markers.
- Added the missing B1/B4 function descriptions reported by their checkers.
- Split B2 pid_apply into torque, breakaway, slew and reverse-trim helpers.
  Their order, gains, thresholds and output limits were retained. All B2
  functions now satisfy the checker's 100-line limit.
- Extracted B4's acquisition-deadline wait and flattened the height update's
  nesting. The same clock checks, overrun handling and height updates remain.
- Removed a redundant unsigned-int cast in the B4 native event mask.
- Corrected B2's false positives on #if and its missed split-line function
  definitions. Regression tests cover both cases.
- Corrected B4's blanket rejection of explicit-width unsigned-int bit-fields.
  These native records remain packed; no binary layout or bit widths changed.
- Made B5 source-inspection tests tolerate the new layout and adjacent C
  string literal wrapping. Existing policy and compiled behavioral checks
  were retained.

Preservation check
140/148 application files retain the same non-brace C tokens when comments
and adjacent string wrapping are normalised. Of the eight other files,
four only change compile-time diagnostic strings. The four functional-source

This token check supplements behavioral tests; it is not proof of runtime
or on-car timing equivalence.

Remaining work before claiming full BARR-C compliance
The broad heuristic scan still reports 2,509 candidates in
 after_application_candidates.txt. These are not 2,509 confirmed defects:
 its parser is incomplete and its naming/interface assumptions are B4-specific.
However, actual unresolved issues remain outside the selected layout scope,
including B5 mixed-case types (e.g. S5Error), Boolean names without b_
(e.g. initialized in s5_navigation.c), function documentation, logical
operand parentheses, constant-first equality comparisons, deep nesting,
and shared/legacy module interfaces. Resolve the real cases or explicitly
review and approve project-specific deviations; do not call the whole
repository fully compliant based on passing the selected checkers.
Kernel/SDK/vendor code, cast ranges, concurrency and ISR ownership still
require their own review. Existing convention documents are not new approval
of exceptions. Earlier demo evidence does not validate this rebuilt image.
